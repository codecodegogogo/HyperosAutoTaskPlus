# Hyper自动任务增强

一个 LSPosed 模块，给 HyperOS「安全服务」里的**自动任务**补了几个原生没有的功能。

- 目标版本：安全服务 12.2.2-12.3.2之间的包、12.8.6、13.5.9 与 13.6.0，包名 `com.miui.securitycenter`
- 模块包名：`io.github.codecodegogogo.HyperosAutoTaskPlus`
- 当前版本：1.9.3，「发送邮件」改用原生「打开应用」图标；保留短信发送记录修复和邮件功能
- 没有独立界面，功能入口在安全服务的「自动任务」中；安装后按下面的作用域说明启用并重启手机

## 安装与 LSPosed 作用域

在 LSPosed 中启用「Hyper自动任务增强」，进入本模块的作用域列表，按使用的功能勾选：

| 应用 / 作用域 | 包名 | 何时需要勾选 |
| --- | --- | --- |
| **安全服务** | `com.miui.securitycenter` | **所有功能都必须勾选**，自动任务的选项、编辑和执行在这里接入 |
| **系统界面（SystemUI）** | `com.android.systemui` | 使用 **解锁失败次数** 及其配套的 **成功解锁时** 退出条件时额外勾选 |
| 系统桌面 | `com.miui.home` | 当前没有需要勾选桌面的功能，也没有向桌面注入的代码 |
| Android 系统 / 系统框架 | `android` | 当前不需要勾选 |
| 任务中选择的其它应用 | 对应应用包名 | 冷启动、杀死应用等条件不需要把目标应用加入作用域 |

**系统界面和系统桌面是两个不同的应用。** 解锁失败事件来自系统界面的锁屏认证流程，
需要勾选的是 `com.android.systemui`。修改作用域或更新模块后重启手机，使对应进程重新加载模块。

### 每项功能需要的作用域

| 自动任务选项 / 功能 | 安全服务 | 额外需要系统界面 |
| --- | --- | --- |
| 「启动 / 离开应用」条件搭配「打开应用」结果 | 必须 | 否 |
| 冷启动应用、杀死应用 | 必须 | 否 |
| 隐身模式 | 必须 | 否 |
| 屏幕状态：亮屏时间、息屏时间 | 必须 | 否 |
| 退出条件的添加、修改、删除与勾选 | 必须 | 按选中的具体条件决定；编辑功能本身不需要 |
| 时间间隔 | 必须 | 否 |
| 设备动作：翻转、摇晃；光线阈值 | 必须 | 否 |
| 到达地理围栏、离开地理围栏 | 必须 | 否 |
| 录音、录屏、截图、拍照 | 必须 | 否 |
| 打电话、发送短信（正文、当前位置） | 必须 | 否 |
| 发送邮件（正文、当前位置、环境照片） | 必须 | 否 |
| 播放音频、发出通知及文件保存通知 | 必须 | 否 |
| **解锁失败次数**（PIN、密码、图案、指纹、人脸合并统计） | 必须 | **是** |
| **成功解锁时**（解锁失败次数对应的退出条件） | 必须 | **是** |

例如「解锁失败 3 次 → 发送带环境照片的邮件」需要同时勾选安全服务和系统界面，
额外作用域来自解锁失败条件；「时间间隔 → 发送邮件」只需要安全服务，无需系统桌面。
仅勾选安全服务也能看到解锁失败选项，但缺少 SystemUI 的事件采集，无法正常更新失败次数和成功解锁状态。

截图、录屏和悬浮通知虽然调用系统服务或由系统显示，仍在安全服务中发起，**不因此增加 SystemUI 作用域要求**。
作用域只决定模块注入哪些进程；定位、相机、录音、短信、通知等访问权限，以及邮件所需的网络和 SMTP 设置仍需分别满足。
以上对应关系依据当前 [模块入口](module/src/io/github/codecodegogogo/HyperosAutoTaskPlus/MainHook.java)
和 [推荐作用域](module/res/values/strings.xml) 核对。

## 增加的功能

### 1. 「启动应用 / 离开应用」条件可以搭配「打开应用」结果

原生：条件选了「启动应用」或「离开应用」后，结果列表里的「打开应用」会被置灰。
现在：不再置灰，可以做“打开 A 时自动打开 B”这类任务。

### 2. 新增两个条件：冷启动应用、杀死应用

在「添加条件 → 事件」里，紧跟在原生「启动应用 / 离开应用」之后。

- **冷启动应用**：应用进程从无到有（被加载进内存）时触发
- **杀死应用**：应用的所有进程都被清出内存时触发

和原生「启动 / 离开应用」的区别：原生看的是前后台切换，这两个看的是进程是否存在。
支持多选应用，支持「退出时恢复」（两者互为退出条件）。

### 3. 新增结果：隐身模式

在「添加结果 → 设置项」里，紧跟在「定位」之后，可选「开启」或「关闭」。

隐身模式是系统权限中心里那个开关（开启后所有应用无法录音、定位、拍照），系统只在设置页给了开关，
没有快捷入口。现在可以在自动任务里自动开关它，勾选「退出时恢复」会在任务退出时切回相反状态。

### 4. 新增条件：屏幕状态

在「添加条件 → 事件」里，紧跟在「锁屏」之后。界面和「电量」条件一样是两张卡片：

- **亮屏时间**：屏幕持续点亮了指定时长后触发
- **息屏时间**：屏幕持续熄灭了指定时长后触发

时长在输入框里填数字，单位可选秒 / 分钟 / 小时 / 天，填 0 表示一进入该状态就触发。
勾选「退出时恢复」时，退出条件是相反的状态（例如「息屏 10 分钟」的退出条件是「亮屏时」）。

### 5. 退出条件可以自定义

原生：勾选「退出时恢复」后，退出条件只能是每个触发条件的反向条件（自动生成、不能改、不能删）。
现在退出条件列表和触发条件列表一样可以操作：

- 列表末尾有「添加条件」，可以额外加任意条件作为退出条件（自定义时间除外）
- 点已有的退出条件可以修改，右侧有删除按钮，自动生成的那条也能删掉换成别的
- 有多条时每条前面有勾选框，勾选的才生效

触发条件之间是「与」（全部满足才执行），退出条件之间是「或」（勾选的任一满足就恢复），和原生一致。

### 6. 时间间隔条件

在「添加条件 → 情境」里，可设置每隔多少秒 / 分钟 / 小时 / 天触发。
时间间隔没有反向状态，也不能添加为退出条件。

### 7. 传感器条件

新增「传感器」分类，包含设备动作（翻转 / 摇晃）和光线阈值。
仅在有启用的对应任务时监听传感器；光线条件可生成相反方向的退出条件。

### 8. 地理围栏条件

在原生「离开某地」之后新增「到达地理围栏 / 离开地理围栏」。复用原生地址选择和围栏判断，
半径可在 50～50000 米之间设置，默认 500 米。设备没有原生地图选点能力时不显示。

### 9. 设备操作结果（1.3.0）

**作用域：安全服务。** 以下结果本身均无需额外勾选系统界面或系统桌面；与其它条件组合时，按条件补齐作用域。

在「添加结果 → 功能」末尾新增以下操作，添加后可以在任务编辑页再次修改：

| 结果 | 配置与行为 |
| --- | --- |
| 录音 | 开始 / 停止，用麦克风录制为 M4A |
| 录屏 | 开始 / 停止，录制屏幕画面为 MP4，当前不包含音轨 |
| 截图 | 无声获取当前屏幕，保存为 PNG 到 `Pictures/Screenshots`，通知可查看文件 |
| 拍照 | 前置 / 后置摄像头可多选，各拍一张 JPEG；同时选择时先后置、再前置 |
| 打电话 | 手动输入一个电话号码，触发时直接拨号；SIM 卡沿用系统拨号设置 |
| 发送短信（1.9.1 调整） | 输入号码和补充正文，可勾选当前位置；仅发送普通短信，全部分段成功后检查并保存本机已发记录 |
| 发送邮件（1.9.0） | 配置 SMTP、发件 / 收件邮箱和授权码，填写主题与补充正文，可独立勾选当前位置、环境照片 |
| 播放音频（1.5.0） | 调用系统文件管理选择本地音频，任务触发时按媒体音量播放一次 |
| 发出通知（1.6.0） | 自定义一段文字，支持换行，触发时显示系统标准通知，长文本可展开 |

录音保存在 `Music/HyperosAutoTaskPlus`，录屏和照片保存在 `DCIM/HyperAutoTask`，完成后通过
MediaStore 发布，文件管理器 / 相册可以找到。失败的媒体文件会清理，不留下可见的半成品。

录音、录屏运行时显示持续通知，点按通知即可停止并保存。同一种录制同时只保留一个会话：
重复启动不会重置文件，其他任务也不会抢走录制归属。显式「停止」结果可停止本模块当前的对应录制；
「退出时恢复」则只停止该任务自己启动的录制。停止操作不会反向开启，截图、拍照、电话、短信、邮件、通知恢复时不执行。

从 1.7.0 起，录音、录屏和拍照保存完成后会显示系统标准的「已保存」通知，附带 **查看文件** 按钮。
点按钮或通知正文即可通过系统选择的播放器 / 图片查看器打开对应文件；展开通知可看到文件名和保存目录。
每个文件独立关联通知，前后摄像头同时拍摄时分别显示。停止录制后移除的是正在录制通知，已保存通知可以保留或手动清除。
通知使用安全服务下的「自动任务保存的文件」类别；关闭该类别只影响完成通知，已经保存的文件不受影响。

从 1.8.1 起，截图通过安全服务已有的系统截屏接口直接获取画面，以 PNG 保存到 `Pictures/Screenshots`，
不触发系统截图广播及其提示音。保存后继续显示无声的「截图已保存」通知，附带 **查看文件** 按钮。
通知直接关联本次保存的文件，不再轮询媒体库猜测归属，也不会影响同时手动截图或正在进行的录屏 / 投屏。
系统接口不可用或没有返回画面时明确提示失败，不退回有声截图；受保护画面仍受系统截屏规则限制。

录屏使用安全服务已有系统权限创建独立 MediaProjection，会避让正在进行的系统录屏或投屏，
不会停止其它应用的录制。录屏尺寸按启动时的方向确定，长边最多 1920 像素，录制中不动态切换方向。
从 1.8.1 起，前后置拍照先关闭本次相机会话的快门音，不修改手机音量；1.9.0 的邮件环境照片沿用这一方式。
系统拒绝关闭快门音时取消拍照并提示，不回退到有声拍摄。相机被占用或所选摄像头不存在时会报错；多选时一个摄像头失败仍会尝试另一个。
旧版任务的前置 / 后置单选设置会保留，编辑时可以改为多选。
拍照、截图的结果图标与录屏保持一致，包含正常、禁用和半透明三种状态。
从 1.8.2 起，录音结果改用原生「调节音量」图标，同样包含三种状态。

「播放音频」通过 Android 系统文件选择器选取文件，并申请持久读取授权，任务保存后、安全服务
重启后仍可使用同一文件。取消选择不会覆盖原配置；文件被删除或访问授权被撤回时会提示播放失败。
选择期间如果编辑页被系统重建，会提示重新选择，避免把结果写回失效的草稿。
系统解码器支持 MP3、AAC/M4A、WAV、FLAC、OGG/Opus、AMR 等常见格式，具体编码兼容性以设备为准。
默认不循环、不修改媒体音量；播放完毕自动释放资源，通知栏可点按停止。
本模块同一时间播放一段音频，新播放替换上一段；「退出时恢复」仅停止本任务的播放。
收到音频焦点中断（例如来电）时停止播放；系统要求降低音量时暂时降低播放器音量。

「发出通知」填写正文后保存，标题为「自动任务」，使用系统标准通知及大文本展开样式，可在通知栏手动清除。
通知归属安全服务，使用独立的「自动任务通知」类别，声音等提醒效果遵循系统通知设置。
同一任务再次触发会更新自己的通知，不同任务分别显示；任务退出时不重复发送，也不撤回已发出的通知。
内容不能全为空白，取消编辑保留原内容；安全服务或该通知类别被关闭时会提示开启。

从 1.7.1 起，本模块的所有系统通知都默认使用高重要级别（`IMPORTANCE_HIGH`）：自定义通知、
正在录音 / 录屏、正在播放音频，以及录音 / 录屏 / 拍照 / 截图保存完成通知。
更新并重启后首次触发对应通知时会使用固定的新渠道 ID，解决旧渠道已经保存为普通 / 低重要级别的问题。
旧渠道保留，避免删除仍在通知栏中的文件通知；新的渠道不会每次执行都重建成不同 ID，后续系统设置会保留。
高重要级别允许系统显示悬浮横幅，是否实际弹出还取决于安全服务的「悬浮通知」、对应类别设置及勿扰模式。
从 1.8.0 起还为通知添加 MIUI / HyperOS 的悬浮提示标志；系统不提供扩展接口时仍发送标准高优先级通知。
截图、拍照等文件已保存但通知被关闭时，会提示开启安全服务及「自动任务保存的文件」类别的通知。
如更新后仍无横幅，可长按对应通知进入类别设置，检查重要程度及悬浮通知；无需开启应用悬浮窗权限。
1.8.1 为照片、截图及其它媒体保存通知启用固定的新无声渠道，保留高重要级别和悬浮提示，默认不响铃、不振动。
旧渠道保留，已有文件通知仍可打开；自定义「发出通知」继续按其独立类别的设置提醒。

#### 发送短信与位置正文（1.9.1 调整）

「发送短信」保留号码、补充正文和 **发送当前位置** 选项，隐藏 **发送环境照片** 及底部全部说明文字。
运行时忽略旧任务保存的照片标记，不启用相机或彩信；再次编辑并保存时会清除该标记，取消编辑仍保留原配置。
旧任务缺少位置字段时默认不勾选；编辑时勾选位置可留空补充正文，否则需要填写文字。

短信与邮件沿用同一正文格式，自动添加「本设备触发HyperosAutoTaskPlus行为」，手填文字作为补充放在下一行。
勾选位置时，正文使用以下格式：

```text
本设备触发HyperosAutoTaskPlus行为，我的地址为（地点）（经度：…，纬度：…）（【https://uri.amap.com/marker?position=…】）
手填的补充内容（有填写时）
```

仅在任务发送时请求定位，最多等待 30 秒，只接受 15 秒内、精度不低于 200 米的位置。
通过系统地址服务解析地点，最多额外等待 6 秒；无法解析时写明「地点暂无法解析」，仍保留有效经纬度和地图链接。
定位权限不足、定位关闭或没有取得有效位置时，整条消息不发送并提示原因。
正文经纬度保留 Android 返回的 WGS-84 坐标；中国范围内的高德链接转换为 GCJ-02，避免直接使用 GPS 坐标产生偏移。

短信使用默认短信 SIM 卡，长内容按系统规则分段；未勾选位置时只包含固定开头和补充文字。
只有全部分段的系统发送回调成功，才处理本机的「已发送」记录，不代表收件人已阅读；没有收到结果时提示未知，不自动重发。

**1.9.1 补充本机发送记录：** 某些系统会发出短信，却不自动把安全服务发送的内容写入短信数据库。
本版本读取发送回调中的系统记录地址，先确认系统是否已经保存；缺少记录时，补写一条完整的已发送短信，
包含收件号码、实际发送正文、发送时间和短信 SIM 信息。长短信合成一条记录，连续发送相同内容仍分别保留。
发送失败、部分分段失败或结果未知时，不补写成已发送记录，也不会为保存记录再次发送短信。
短信记录的读写使用安全服务现有权限，不修改默认短信应用或自动更改系统权限。
若系统拒绝读取或写入，会明确提示「短信已发送，但未能保存到本机短信记录」，与发送失败区分。
本地回归覆盖分段结果与记录去重；目标手机的短信数据库权限及短信应用展示仍需真机验证。

此前设备反馈为普通短信可成功、彩信发送失败，真实失败原因尚未定位。旧彩信实现仍保留在仓库中，
1.9.0 暂停短信入口对它的调用，本次调整不表示已经修复彩信问题。



#### 发送邮件（1.9.0）

在「添加结果 → 功能 → 发送邮件」配置独立邮件结果，只需要 **安全服务** 作用域。
邮件通过网络连接邮箱的 SMTP 服务，不依赖短信 SIM 卡，也无需勾选系统桌面。

先在发件邮箱中开启 SMTP，并取得服务商提供的 **SMTP 授权码或应用密码**。填写单个发件邮箱、单个收件邮箱，
以及 SMTP 登录账号；账号留空时使用发件邮箱。当前支持 SMTP 密码认证，**不支持 OAuth 登录**。

| 邮箱预设 / 配置 | SMTP 主机 | 端口与加密方式 |
| --- | --- | --- |
| QQ 邮箱 | `smtp.qq.com` | `465`，SSL/TLS |
| 163 邮箱 | `smtp.163.com` | `465`，SSL/TLS |
| 其它邮箱 | 填写服务商提供的主机名，不包含网址前缀或端口 | 按服务商要求填写，支持自定义端口 |

**SSL/TLS** 从建立连接时就加密，常用端口为 `465`；**STARTTLS** 先建立 SMTP 连接，再升级为加密连接，
常用端口为 `587`。两种方式都在 TLS 校验成功后才发送账号和授权码，服务器不支持所选加密方式时停止发送，
不会降级为明文认证。预设仅填写服务器参数，仍需填写自己的邮箱和授权码。

邮件主题必填，支持中文和表情；补充正文可留空，支持换行。**发送当前位置** 和 **发送环境照片** 默认勾选，
可分别开启或关闭，四种组合均支持。位置与固定正文使用上面的格式；勾选照片时拍摄一张后置环境照片，
以 JPEG 附件发送，不另存到相册。两项都关闭时发送固定开头与补充正文。所选定位或拍照失败时整封邮件不发送，并提示原因。

**点击确定只保存配置，不会发送测试邮件；任务实际触发时才发送，退出时不会再次发送。**
取消编辑不改变原任务；配置无效或授权码保存失败时不覆盖已有配置。

授权码通过本机 Android KeyStore 密钥加密，保存在安全服务私有数据中，并绑定 SMTP 主机与账号。
任务数据库、Gson / Serializable 参数和导出内容只保存凭据引用，不包含明文授权码。
更换发件邮箱、登录账号或 SMTP 主机后需重新输入授权码。导入任务不会带入授权码；清除安全服务数据、换机，
或导入到没有对应本机凭据的环境后，需要重新配置。已有授权码不会回填到编辑框，留空表示沿用当前有效凭据。

邮件按顺序处理，最多同时保留 **1 封正在处理、3 封等待**；队列已满时提示本次未加入。
提示「邮件已交给发件服务器」只表示 SMTP 服务器接受了邮件，**不代表已到达收件箱**，仍需检查收件箱和垃圾邮件。
服务器是否接收无法确定时会提示「发送结果未知」，不会自动重试，以免重复发送。
本轮尚未在真实手机和真实邮箱上验证发送、权限、定位及照片附件，实际可用性还需在目标设备检查。

这些操作都在安全服务进程执行，依赖该设备实际授予安全服务的权限。通知被关闭时不会开始录制；
短信在没有默认短信 SIM 卡时发送失败。系统拒绝操作时会显示失败提示，并在 `HyperAutoEnh` 日志里记录原因，
日志不主动记录号码、消息正文或邮件授权码。号码、邮箱、服务器和正文等普通设置沿用原生自动任务的数据库保存方式。

### 10. 解锁失败次数条件（1.4.0，需要额外勾选系统界面）

**作用域：安全服务 + 系统界面。** 本节的「解锁失败次数」和对应「成功解锁时」退出条件都需要这两个作用域。

从 1.8.3 起，点击「解锁失败次数」或「成功解锁时」后，弹出的编辑框始终显示所需作用域、包名和重启说明，
已有计数时也会显示。选项名称和任务摘要保持简洁，不附加作用域标注。

在「添加条件 → 事件 → 解锁失败次数」中设置 **1～999 次**，默认 3 次。
判断是「连续失败次数 ≥ 所选次数」：选 3 时，第 3 次失败即满足。

- PIN、密码、图案、指纹和人脸的锁屏认证失败共用一个计数。
- 成功解锁后清零；息屏、再次亮屏、切换解锁方式不会清零。
- 达到阈值时通知自动任务引擎，继续失败不会反复产生相同的阈值变化；与其它触发条件仍按原生「与」关系组合。
- 勾选「退出时恢复」会生成「成功解锁时」退出条件，解锁后可停止该任务启动的录音 / 录屏。
- 取消识别、识别超时、传感器错误、应用内验证和其它用户的认证不混入当前用户统计。

这项功能需要在 LSPosed 中为模块同时勾选 **安全服务 `com.miui.securitycenter`** 和
**系统界面 `com.android.systemui`**，更新作用域后重启手机。只勾选安全服务能看到条件，但不能获得失败事件。

SystemUI 通过 `LockPatternUtils.reportFailedPasswordAttempt` 和 `KeyguardUpdateMonitor` 的
指纹 / 人脸失败汇总方法采集；只保留计数和成功解锁序号，经本模块专用 Secure 设置交给安全服务。
每个手机用户分别存储，进程重启后继续累计，不采集密码或生物特征。成功解锁的清零依据系统 `USER_PRESENT` 广播。
HyperOS 如改动这些认证入口，对应方式会在 LSPosed 的 `HyperAutoEnh` 日志中报告 hook 失败，需要按该版本适配。
当前已核对 Android 15/16 的标准入口；各 HyperOS 机型实际是否经过这些入口仍需真机验证。
